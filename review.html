The component is small, readable and accessible in the basics. The main problem is that its "Get Started" button belongs to an older, front-end-only version of the app and is not connected to the real enrollments the app now stores.

Findings

High

"Get Started" is not connected to real enrollments

Lines 65, 84–94 · with App.jsx toggleStarted

"Started" comes from startedCourseIds, an in-memory list in App.jsx. It is never saved, it resets on logout or reload, and it has nothing to do with the enrollments table. So:

  • A student taking a course (it appears under "Courses I'm taking") still sees Get Started for it here.
  • Clicking Get Started does not enroll them; the course never reaches their dashboard.
  • Faculty and directors see the same button, though it means nothing for their roles.

Suggestion: for students, pass the enrolled course IDs (from GET /api/student/courses) and have the button call enrollInCourse, showing "Enrolled" afterwards. Hide the button for other roles. Then remove startedCourseIds / toggleStarted from App.jsx.

Medium

Scroll arrows show and do nothing when there is no carousel

Lines 39–44, 10–15

The left and right buttons always render. While loading, on error, or when filters match nothing, trackRef.current is null, so clicking them silently does nothing. They also stay enabled at the start and end of the row.

Suggestion: render the arrows only when the list is showing (catalog.status === 'success' && courses.length > 0). Optionally track scrollLeft on the track's scroll event and disable the arrow that can't move.

Medium

Empty state blames filters even when there are no courses

Lines 55–61

Now that courses come from the database, the catalog can be empty. In that case the user sees "Nothing matches that combo. Loosen the filters" and a "Show me everything" button that changes nothing, even with no filters set.

Suggestion: branch on hasFilters:

{hasFilters ? (
  /* current "Nothing matches that combo" + Show me everything */
) : (
  <p className="empty-state">No courses yet. Check back soon.</p>
)}
Low

Card gap is hard-coded in two places

Line 16 · styles.css .carousel { gap: 20px }

The scroll step adds a literal 20 that has to match the CSS gap. If the gap changes, each arrow click drifts off the card edge. (Scroll snapping hides most of this today.)

const gap = parseFloat(getComputedStyle(track).columnGap) || 0;
const step = card ? card.getBoundingClientRect().width + gap : track.clientWidth * 0.8;
Low

Toggle button changes its label and its pressed state

Lines 89–90

The button uses aria-pressed and also swaps its accessible name between "Get Started with X" and "Started X". Screen readers then announce, for example, "Started MERN, toggle button, pressed", which repeats the state. A toggle should keep one name and let aria-pressed carry the state.

Suggestion: use a fixed aria-label={`Start ${course.title}`}. If finding 1 turns this into an "Enroll" action, drop aria-pressed and disable the button once enrolled.

Low

"Try again" hides the list and the subtitle reads "0 of 0"

Lines 27–29, 48, 55

useRecords keeps the old records but sets status to 'loading' on reload. This component only renders the list on 'success', so any reload blanks the row. While the first load is running with filters active, the subtitle says "Showing 0 of 0 courses".

Suggestion: render the list whenever catalog.records.length > 0 and show the loading message only when there are no records yet. Show the "Showing X of Y" text only after a successful load.

Low

Indentation inside the map

Lines 66–98

The returned <li> sits at the same indentation as return (, which makes the block hard to scan. The started variable could also move into a small CourseCard component, letting the map be courses.map((course) => <CourseCard … />).

What's working well

  • Loading, error (with retry) and empty states are all handled, with role="status" / role="alert" for screen readers.
  • Arrow scrolling respects reduced-motion settings through scrollBehavior().
  • The section is labelled by its heading, the list has an aria-label, and icon-only arrows have text labels.
  • Stable ids (course-…, course-…-cta) let "Resume" scroll to and focus a specific card.
  • Course art is shared with the picker through CourseArt, so the two stay consistent.
